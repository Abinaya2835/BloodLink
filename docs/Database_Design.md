# BLOODLINK – DATABASE DESIGN DOCUMENT

## 1. Introduction

BloodLink is a Blood Donor and Blood Bank Management Platform developed using the MERN stack. The application connects blood donors and blood banks through a centralized web platform.

The database stores and manages user accounts, donor information, blood bank details, blood inventory, and blood requests. It helps organize blood-related information and supports efficient communication between donors and blood banks.

## 2. Database Technologies

| Component | Technology |
|---|---|
| Database | MongoDB |
| Database Type | NoSQL |
| ODM | Mongoose |
| Backend | Node.js |
| Backend Framework | Express.js |
| Frontend | React.js |
| Authentication | JSON Web Token (JWT) |

MongoDB is used because it stores data in flexible document-based collections. Mongoose provides schema definitions, validation, and database operations.

## 3. Database Structure

The BloodLink application uses the following main collections:

1. User
2. Donor
3. BloodBank
4. BloodInventory
5. BloodRequest

Each collection stores information related to a particular part of the application.

### 3.1 User Collection

The User collection stores the basic account information of registered users.

**Purpose:**
- Store user registration details.
- Support login and authentication.
- Identify the type of user.
- Manage access based on user roles.

**Main fields:**

| Field | Description |
|---|---|
| _id | Unique identifier generated by MongoDB |
| name | Full name of the user |
| email | Email address of the user |
| password | Hashed password |
| role | User role (donor, bloodbank, or admin) |

### 3.2 Donor Collection

The Donor collection stores additional information about registered blood donors.

**Purpose:**
- Store donor-specific information.
- Maintain blood group details.
- Store donor contact and location information.
- Track donor availability.

**Main fields:**

| Field | Description |
|---|---|
| _id | Unique donor record identifier |
| user | Reference to the associated User document |
| bloodGroup | Blood group of the donor |
| phone | Donor contact number |
| city | Donor's city |
| state | Donor's state |
| isAvailable | Indicates whether the donor is available |
| createdAt | Record creation timestamp |
| updatedAt | Last update timestamp |

**Supported blood groups:**
- A+
- A-
- B+
- B-
- AB+
- AB-
- O+
- O-

### 3.3 BloodBank Collection

The BloodBank collection stores information related to registered blood banks.

**Purpose:**
- Maintain blood bank profiles.
- Store blood bank-related information.
- Associate blood bank details with registered user accounts.
- Support blood inventory management.

The BloodBank collection is associated with the corresponding User account through a reference.

### 3.4 BloodInventory Collection

The BloodInventory collection manages blood stock information maintained by blood banks.

**Purpose:**
- Maintain blood availability information.
- Organize inventory according to blood groups.
- Support inventory updates.
- Help blood banks manage their available stock.

Inventory records are associated with blood bank information.

### 3.5 BloodRequest Collection

The BloodRequest collection stores blood requests submitted through the application.

**Purpose:**
- Record blood requirements.
- Maintain information about blood requests.
- Associate requests with relevant users or blood banks.
- Support request tracking and status management.

The collection supports the blood request management functionality of BloodLink.

## 4. Relationships Between Collections

BloodLink uses document references to establish relationships between related collections.

| Relationship | Description |
|---|---|
| User – Donor | A donor record is associated with a User account. |
| User – BloodBank | A blood bank profile is associated with a User account. |
| BloodBank – BloodInventory | Inventory information is associated with a blood bank. |
| User – BloodRequest | Requests are associated with the relevant user information. |

These relationships help maintain organized data and connect information across different application modules.

## 6. Data Validation

Mongoose schemas are used to define and validate the data stored in MongoDB.

The application uses validation to maintain data consistency.

Examples include:

- Required fields for user registration.
- Valid email and password inputs.
- Supported blood group values.
- Required donor contact and location details.
- Valid user roles.
- References between related documents.

## 7. Database Security

BloodLink implements security measures to protect user information.

- Passwords are hashed using bcrypt before storage.
- JWT-based authentication is used to verify users.
- Role-based authorization helps restrict access to protected features.
- Backend middleware checks authentication and administrative permissions.
- Environment variables are used to store sensitive configuration values.
- Database access is handled through the backend server.

## 8. Database Operations

The application performs standard database operations through Mongoose.

| Operation | Description |
|---|---|
| Create | Register users and add relevant records. |
| Read | Retrieve donor, blood bank, inventory, and request information. |
| Update | Modify profile, inventory, and request information. |
| Delete | Remove records where permitted. |

These operations support the main functionalities of the BloodLink application.

## 9. Advantages of the Database Design

- Organized storage of application data.
- Flexible document-based data management.
- Separation of user and role-specific information.
- Easy retrieval of donor and blood bank details.
- Support for blood inventory management.
- Efficient tracking of blood requests.
- Improved data consistency through schema validation.

## 10. Conclusion

The BloodLink database is designed using MongoDB and Mongoose to manage donor details, blood bank profiles, blood inventory, user accounts, and blood requests.

The collection-based structure provides flexibility, scalability, and organized data management. The use of document references, validation, password hashing, and JWT authentication helps support a secure and efficient blood donor and blood bank management platform.
